# 训练闭环增强版设计

## 目标

把 Healthy Fitness Coach 从“能够给出建议并读取训练数据”提升为可审计的训练闭环：数据先通过账号、日期、单位和来源边界校验，再生成指导、总结和视觉资产；任何缺失、过期或不可比数据都必须显式降级，而不是被估算成确定结论。

## 范围

### 1. 可信数据层

- 一次日期范围、趋势或训练 DNA 操作固定一份凭据快照，禁止同一操作混用账号。
- 鉴权失败、会员失效和速率限制不静默回退成普通缓存；旧缓存必须标记为不可用于“最新”分析。
- 训记写回响应中的每条记录都必须能解析出同一有效日期；只缓存经过来源和日期过滤的模型数据。
- 主动作表现统一为 `weight_kg`，保留原始单位和原始文本用于审计。
- 计划频率、时长、距离、心率等输入限制为有限且非负的合理值。
- 本地缓存指纹只能是 64 位十六进制哈希；个人照片测试目录默认不进入版本控制。

### 2. 健身指导层

新增可复用的指导决策模块，输出固定四段：

1. 观察到的事实；
2. 受证据支持的判断；
3. 下一次训练的具体行动；
4. 下一次复盘需要记录的验证字段。

指导按增肌/力量、有氧/耐力、减脂/活动量、混合训练四类路由，并复用安全筛查、恢复和动作替代边界。无结果字段时不得输出“对用户有效”的高置信度结论。

### 3. 训练总结层

提供统一的周/月/年度摘要模型，包含训练天数、有效训练场次、阻力训练量、有氧时间、部位覆盖、主动作表现、依从性、数据完整度和下一周期建议。缺失日期、休息日、未知记录和跨单位记录分开统计。

### 4. 训练视觉层

视觉输入继续支持无图、单图和多图。新增统一的 `training_summary` 数据契约，让信息图、简约分享图和照片拼贴共享同一事实源；保留 1:1、3:4、9:16 三种输出比例。对空数据、长中文、跨年热力图和异常数字输出明确的 no-data/降级状态。

## 关键接口

- `createTrainingService()`内部新增单次操作的 credential snapshot 传递。
- `analyzeTrainingRange()`输出统一的 `weight_kg` 主动作表现和数据质量字段。
- 新增 `buildTrainingGuidance(input)`，返回 facts/judgment/action/validation。
- 新增 `summarizeTrainingRange(input)`，返回 week/month/year 通用摘要。
- 视觉编译器接受 `training_summary`，不得凭空生成训练日期、容量或进步值。

## 测试策略

- 先写失败测试，再实现：凭据轮换、鉴权失败、写回 date-less、Garmin 回显、lb/kg、负计划频率、空数据视觉和跨年热力图。
- 保持现有 Node 单元测试、MCP 测试、Gherkin、PNG/SVG 视觉门、知识库门和变异测试。
- 增加指导与摘要的确定性单元测试，以及跨层契约测试，确保总结和视觉资产使用同一指标。
- 交付前运行 V8 行/分支/函数覆盖率、Python 编译、Skill 校验、密钥扫描、Markdown 链接检查和发布包检查。

## 非目标

- 不实现医学诊断、康复处方、药物/科技使用建议。
- 不在 Skill 内加入爬虫或绕过平台反爬工具。
- 不把个人照片、训记缓存、API Key 或用户报告写入公开仓库。
