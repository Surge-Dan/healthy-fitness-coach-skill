# 健康健身 Skill：可视化报告与分享图设计规格

## 1.目标与边界

### 目标

把训记或手工训练数据转化为两类高质量视觉产物：

1. **分析报告**：Markdown 主文档 + 可嵌入 SVG/PNG 图表 + 可选本地 HTML 面板。
2. **分享图**：基于训练数据、训练洞察或用户健身照片，生成适合社交媒体发布的 1:1、9:16、3:4 图片。

第一版必须做到：数据准确、图表可复现、比例可控、风格不老套、失败可回退、个人数据不进入公开仓库。照片艺术化属于增强能力：具备 Agent 图像生成工具时启用；不可用或失败时回退到本地照片排版。

### 非目标

- 不复制训记、Spotify Wrapped 或任何参考 Skill 的具体界面、插画、文案和素材。
- 不把估算训练量包装成医学结论或精确生理指标。
- 不把用户照片、API Key、训练 ID、原始缓存提交到 GitHub。
- 不在第一版实现在线分享链接、社交平台自动发布或云端图片存储。

## 2.设计研究结论

公开案例显示，运动类社交视觉通常依赖强信息层级、运动场景语义、对比鲜明但受控的色彩和适合快速浏览的构图；体育 stat card 的有效做法是把关键数字和语境图像绑定，而不是堆满指标。[Behance Gym Social Design](https://www.behance.net/gallery/247306061/Gym-Social-Design-Branding-High-Impact-Campaign)、[Basketball Forever Branding](https://www.ishaanmishra.com/project/forever)

数据叙事方面，年终回顾和微型信息图倾向于使用少量核心数字、短句洞察、图表摘要和可分享卡片，而非完整仪表盘的缩小版。[Canva Design DNA 2025](https://www.canva.com/newsroom/news/design-dna-2025/)、[VectoSolve Year-in-Review Graphics](https://www.vectosolve.com/blog/year-in-review-graphics-templates-2025)、[Venngage Infographic Trends](https://venngage.com/blog/infographic-design-trends/)

视觉语言上，深色底+高亮色、编辑化网格、粗细字体对比和微型图表在社交媒体上有较强辨识度；但第一版必须加入留白、叙事短句和风格切换，避免统一套用霓虹渐变。[UIChart Data Visualization Trends](https://uichart.com/blog/data-visualization-trends-2025)、[Canva Design Trends 2026](https://www.canva.com/newsroom/news/design-trends-2026/)

据此形成四条产品原则：

- **先讲一个结论，再展示数据**：一张分享图最多突出1个主结论和3～5个辅助指标。
- **数据与语境绑定**：训练量旁边同时出现训练周期、部位或动作语境，避免孤立大数字。
- **模板是系统，不是套壳**：同一数据可切换不同风格，但字号层级、边距、可读性和事实边界固定。
- **生成要有回退**：图像增强不是报告交付的单点故障。

## 3.用户流程

### 3.1 分析报告

用户提出“分析最近一个月/今年/自定义区间”，Skill：

1. 复用本地训记缓存，仅请求缺失日期。
2. 运行数据质量检查和多维分析。
3. 生成 `fitness-reports/<period>-training-review.md`。
4. 生成同目录下的 `assets/` 图表资源和可选 `dashboard.html`。
5. 在 Markdown 中嵌入相对路径图表，并在结论中标注估算值、缺失记录和不确定性。

### 3.2 分享图

触发词包括“分享图、海报、训练月报、训练战绩卡、发小红书、做一张训练图”等。输入可以是：

- 训练数据/分析报告；
- 用户上传的一张或多张健身照片；
- 数据+照片的组合。

比例规则：用户明确指定比例就只生成该比例；用户要求“一组/三种比例”才生成全部 1:1、9:16、3:4；只说“做分享图”且没有上下文时询问比例。用户未指定风格时，根据内容选择推荐风格并直接生成。

## 4.输出与风格系统

### 4.1 固定画布

| 比例 | 默认像素 | 主要用途 |
|---|---:|---|
| 1:1 | 2048×2048 | 头像墙、朋友圈、方形战绩卡 |
| 9:16 | 1440×2560 | 小红书、Instagram Story、手机长图 |
| 3:4 | 1800×2400 | 小红书图文首图、训练月报海报 |

输入照片不限制尺寸；本地处理使用 cover 裁切、主体保护和安全边距，避免脸部/身体关键部位被裁掉。输出统一为 sRGB PNG；用户需要轻量文件时可另导出 JPG。

### 4.2 第一版风格

1. **Night Performance**：石墨黑、酸橙绿、冷白；大字号数字、细网格、短促英文副标题。适合战绩和月报。
2. **Editorial Training Journal**：暖白、深靛蓝、砖红/荧光黄点缀；衬线标题+无衬线数据；适合长期复盘和照片故事。
3. **Raw Gym Contact Sheet**：深灰底、胶片边框、编号、日期戳、照片切片和小型指标；适合多图训练记录。
4. **Clean Athletic**：米白、钴蓝、橙色；留白更大、图表更克制；适合公开发布和专业教练风格。

5. **My Visual DNA（自适应风格）**：从用户上传照片中提炼专属色板、明暗关系、纹理、构图节奏和情绪，再生成当前用户的视觉Token。它不是一个固定模板，而是根据每次上传的照片动态变化；同一用户多次生成时，可以选择沿用最近一次的风格Token。

风格选择支持自然语言别名，如“酷一点、像杂志、干净、赛博、低调高级、按这张照片的感觉来”。没有照片且没有指定风格时，回到四个预设风格；有照片但没有指定风格时，默认尝试 `My Visual DNA`。不得使用默认火焰、杠铃剪影、爆炸光效、过度渐变和鸡汤长文案作为主视觉。

### 4.2.1 自适应风格提炼流程

用户上传照片后，先经过一个“视觉风格提炼”阶段，再进入分享图排版：

```text
照片
 ↓
图像信号提取：主色/辅色、明暗、对比度、饱和度、纹理、景别、主体位置
 ↓
可选Agent视觉分析：情绪、光线语言、材质、构图节奏、适合的文字安全区
 ↓
StyleToken：palette、contrast、grain、lighting、frame、type_pairing、spacing、motif
 ↓
安全约束：可读性、主体保护、品牌/水印去复制、数据层对比度
 ↓
分享图模板渲染：照片层 + 图表层 + 数据层
```

#### 提取范围

- **色彩**：从照片提取3～5个主色，生成背景色、强调色、辅助色和文字色；必要时降低饱和度，确保数字可读。
- **光线**：识别高调/低调、硬光/柔光、冷暖倾向和局部高光，用于背景渐变、遮罩和阴影方向。
- **材质**：识别胶片颗粒、纸张、金属、混凝土、玻璃等抽象质感，仅生成可复用的纹理参数。
- **构图**：识别主体在左/中/右、近景/中景/全身和视觉留白区域，决定标题、数据卡和图表的位置。
- **情绪与节奏**：将“克制、爆发、松弛、纪实、未来感”等描述映射为边框、线条、字号比例和动势，不复制原图具体元素。

#### StyleToken约束

StyleToken必须是可序列化的结构化对象，例如：

```json
{
  "palette": {"bg": "#17191D", "accent": "#D7FF4B", "secondary": "#7A8BFF", "text": "#F6F7F2"},
  "contrast": "high",
  "lighting": "cool_hard_light",
  "texture": "fine_grain",
  "composition": "subject_right_text_left",
  "type_pairing": "condensed_sans_plus_neutral_sans",
  "spacing": "tight_editorial",
  "motif": "thin_measurement_lines",
  "confidence": 0.86
}
```

Agent只负责给出视觉描述和候选Token；最终颜色、字号、间距、图表和文字由本地模板约束。低置信度字段回退到对应预设风格，避免生成不可读或过度装饰的图片。

#### 版权、隐私和可控性

- 不提取或复制Logo、水印、品牌字体、人物身份或可识别的具体作品构图。
- 用户可以在生成前说“保留原图风格但更简洁”“只借用色彩”“不要颗粒”等自然语言覆盖Token字段。
- StyleToken默认只保存在本次任务目录；用户明确要求“记住我的风格”时，才保存不含原图的抽象Token。
- 原图不进入Git、不写入公开报告；生成失败时回退到照片+预设风格排版。

### 4.3 分享图内容模板

- `monthly-recap`：周期、训练天数、总时长、平均时长、训练频率、部位分布、1句洞察。
- `performance-card`：一个主动作、起始/当前表现、次数或负重变化、记录日期、谨慎的进步措辞。
- `consistency-card`：训练日历热力图、最长连续训练、最长间隔、下周期建议。
- `photo-editorial`：照片主体、日期/训练主题、2～3个数据标签、短句洞察。
- `photo-data-poster`：照片作为背景或裁切主体，前景叠加数据图表和小标签。

所有模板都要求事实来源可追溯到当前分析结果；没有数据时显示“未记录”，不补造数字。

## 5.技术架构

新增一个独立的本地视觉模块，避免把渲染逻辑塞进训记 API 客户端：

```text
Xunji cache / manual log
          ↓
  normalized analytics model
       ↙          ↘
 report renderer   share-card renderer
  (SVG + MD/HTML)       ↓
                  local photo compositor
                         ↓
                 optional Agent imagegen
                         ↓
                    PNG/JPG exports
```

建议目录：

- `healthy-fitness-coach/references/visualization.md`：图表选择、事实边界、可读性规则。
- `healthy-fitness-coach/references/share-cards.md`：风格、模板和自然语言映射。
- `healthy-fitness-coach/references/visual-safety.md`：照片隐私、敏感内容和回退策略。
- `healthy-fitness-coach/assets/share-card-templates/`：SVG/CSS 模板和主题变量。
- `healthy-fitness-coach/references/visual-report.js`：确定性图表/卡片渲染入口。
- `healthy-fitness-coach-plugin/mcp/xunji/src/dashboard.js`：复用同一分析模型，输出报告图表数据；不在 MCP 中保存图片或凭据。

渲染器采用“数据模型→场景模型→模板”的三层边界：同一份分析结果可以输出报告图表和分享卡，模板只负责布局，不重新计算指标。

## 6.照片增强与回退

### 有图像生成工具时

先对照片进行隐私和构图检查，再用固定提示词骨架生成“视觉处理建议”，而不是让模型重写训练数据。生成结果只负责背景、材质、光影或艺术化；姓名、日期、重量、次数等文本由本地渲染器叠加，避免图像模型写错数字。

### 无图像生成工具或生成失败时

本地完成：主体保护裁切、渐变/纹理背景、照片叠层、数据卡片、线性图表、编号和日期戳。报告和分享图仍然正常交付，并在内部标记 `image_enhancement: fallback`，不向用户制造“AI艺术化成功”的错觉。

## 7.错误处理与隐私

- 缺少训记数据：生成“数据不足”卡片，不伪造趋势。
- 缺少日期：图表显示缺失区间，并在报告中说明“无记录不等于休息”。
- 图片尺寸极端：先规范化到安全内存尺寸，再做 cover 裁切。
- 不支持的格式：提示支持的图片格式并保留原文件不变。
- API Key只在请求内存中使用；图片和报告不写入凭据目录，不加入Git。
- 默认输出到本地 `fitness-reports/` 或用户明确指定目录，个人素材不进入 `dist/` 和公开仓库。

## 8.验收标准

### 报告

- 月度和年度报告都能生成至少4种图表：趋势、频率/热力、部位分布、主动作表现。
- 图表在桌面和手机宽度下可读；中文字体、数字和单位不溢出。
- 图表数据与分析模型逐项一致；缺失和估算值有明确标注。
- Markdown、HTML均可脱离API Key打开。

### 分享图

- 1:1、9:16、3:4输出尺寸精确，至少支持PNG。
- 同一份数据切换风格后，数字、日期和事实完全一致。
- 用户上传任意常见尺寸照片均可生成；关键主体不会被默认裁掉。
- 上传照片且未指定风格时，能够先生成StyleToken，再完成照片风格化排版；至少能体现色板、明暗、构图或纹理中的3项，而不是只叠加固定模板。
- 用户可以用自然语言覆盖StyleToken中的单项或多项，如“保留色彩但去掉颗粒”“文字区域留白更多”。
- 未指定比例时会询问；指定比例时不多生成其他尺寸。
- 无图像生成工具时仍能生成完整、可发布的本地排版图。

### 测试

- 单元测试：比例计算、边距、安全区、数值格式化、缺失值和XSS/HTML转义。
- 单元测试：StyleToken默认值、低置信度回退、对比度修正和自然语言覆盖字段。
- 快照测试：每种风格×每种比例至少1个固定数据样例。
- 自适应风格样例测试：至少准备3种明暗/色彩差异明显的照片，检查生成的StyleToken和最终排版确实不同。
- 端到端测试：从缓存数据生成Markdown、HTML和PNG，检查文件存在、尺寸、无Key、无训练ID泄露。
- 人工视觉检查：中文可读性、信息层级、留白、照片主体、社交媒体缩略图辨识度。

## 9.实施顺序

1. 抽离统一分析视图模型和视觉数据契约。
2. 重构报告渲染器，加入SVG图表和HTML面板。
3. 实现确定性分享卡片渲染器和三种比例。
4. 加入4种风格主题与模板选择。
5. 加入照片本地排版和主体保护裁切。
6. 接入可选Agent图像增强与失败回退。
7. 补测试、生成示例、更新SKILL.md和README使用说明。
