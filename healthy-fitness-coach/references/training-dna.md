# 个人训练DNA与长期训练资产

这份文件定义如何把一次性健身问答升级为可持续更新的个人训练系统。它只使用用户明确提供的资料、训练日志、训记数据和后续反馈；缺失信息必须标记为未知，不得用“看起来像”补齐。

## 什么时候读取

以下任务读取本文件：

- 用户说“建立我的训练档案”“提炼我的训练DNA”“记住我的训练习惯”；
- 用户要求长期训练系统、4～8周周期、训练计划版本升级或平台期诊断；
- 用户要求输出多个可保存文件，而不只是一次性回答；
- 训记数据已经积累至少4周，需要把趋势转成长期训练决策。

## Training Loop七步法

1. **安全筛查**：确认年龄范围、红旗症状、近期手术/急性外伤和特殊人群边界。
2. **训练画像**：记录目标、经验、场地、器械、时间、偏好、睡眠、压力和饮食追踪意愿。
3. **目标拆解**：把“增肌、减脂、宽肩窄腰、提升体能”等愿望拆成可观察指标和时间窗口。
4. **训练编排**：按主要目标选择阻力、有氧、功率、间歇、活动度和恢复模块，确定频率、顺序和最低有效版本。
5. **执行辅导**：给出动作/方式、组次或时长、RPE/RIR、休息、替代动作、停止条件和记录字段。
6. **数据复盘**：比较同动作和相近条件，区分事实、推断、不确定性和待验证指标。
7. **周期升级**：每次只调整1～2个变量，记录调整理由、预期影响、回退条件和下一次复盘窗口。

## 八类训练DNA

### 目标DNA

记录当前目标、优先级、期限、成功指标和不可接受的代价。体型愿望不能自动转成固定体重或固定训练天数。

### 约束DNA

记录时间、频率、场地、器械、预算和可用训练窗口。约束用于缩放计划，不把现实限制误判成执行意愿不足。

### 执行DNA

记录用户偏好的器械、动作、训练时长、环境、音乐/跟练、记录方式和不喜欢的内容。偏好用于提高依从性，不覆盖安全边界。

### 阻力反应DNA

按推、拉、蹲、髋主导、单腿和核心等模式记录可比较表现，并分别观察训练量、强度、频率和RPE/RIR。只比较同动作或相近变式，不把不同器械的重量直接当成同一指标。

### 有氧反应DNA

记录低强度、节奏和间歇训练的时长、配速、功率、心率、完成率和第二天反应。力量与有氧必须分开统计，再评估二者的训练顺序和恢复冲突。

### 恢复DNA

从睡眠、压力、训练间隔、RPE、第二天状态和连续表现推断用户对训练量与强度的耐受。恢复DNA是暂定假设，至少经过2～3个复盘窗口才可提高置信度。

### 依从DNA

记录缺席原因、最低有效方案的完成率、用户最容易执行的训练长度和触发条件。计划应优先适应真实生活，而不是要求用户适应理想课表。

### 风险DNA

记录已知的不适动作、疼痛触发因素、红旗筛查结果和需要观察的功能指标。普通不适可以调整负荷和变式；红旗、持续恶化或日常功能受损时停止自动进阶并转介。

## 长期训练资产

建立系统时默认生成或更新以下文件；用户只要求一份报告时不强制生成全部文件。

| 文件 | 作用 | 更新时机 |
| --- | --- | --- |
| `ATHLETE_PROFILE.md` | 用户背景、目标、限制、器械和安全边界 | 建档或关键背景变化 |
| `TRAINING_DNA.md` | 偏好、表现、恢复、依从和风险的当前假设 | 每4～8周或出现明显模式 |
| `CURRENT_PROGRAM.md` | 当前4～8周周期、每周安排、进阶和降级规则 | 新周期或计划变更 |
| `EXERCISE_PLAYBOOK.md` | 常用动作、替代动作、技术提示和不适变式 | 新动作尝试或反馈变化 |
| `PROGRESS_LEDGER.csv` | 日期、动作/有氧、负荷、次数、时长、RPE/RIR和备注 | 每次训练后 |
| `DECISION_LOG.md` | 每次调整的事实、理由、预期和回退条件 | 每次计划调整 |
| `DNA_EVIDENCE.jsonl` | 每条DNA结论对应的日期、记录ID、指标和证据等级 | 每次DNA更新 |
| `DNA_CHANGELOG.md` | DNA版本、变化原因、降级/撤销记录 | 每次DNA更新 |
| `WEEKLY_REVIEW.md` | 周期完成率、训练量、表现、恢复和下一步 | 每周或每4周 |

## 数据和置信度规则

- **事实**：用户原话、训练记录、训记返回结果或明确测量值。
- **推断**：由多个事实支持的解释，例如“连续三周同动作在相近RPE下次数下降，可能存在恢复不足”。
- **未知**：没有数据时写“未知”，不生成假热力图、假进步或假训练偏好。
- **置信度**：单次反馈为低；至少2次相近暴露为中；跨越3～4周且条件可比、存在结果字段并出现可解释变化时才可为高一些。只有固定组次/次数、缺少负重/RPE/时长/距离/心率等结果，最多保持emerging；范围存在缺失日期时也不升级。确定性计算和模型解释必须分开保存。
- **冲突**：用户偏好可以调整动作和表达方式，但不能覆盖安全筛查、指南边界或明确红旗。

## 计划版本管理

每个周期记录：

- 周期名称、日期范围和主要目标；
- 每周训练频率、每次时长和训练类型；
- 主要动作/有氧方式、组次或时长、RIR/RPE和休息；
- 进阶触发器、降级规则和最低有效版本；
- 本周期只验证的1～3个指标；
- 结束时保留、修改、删除和待验证的内容。

不要因为单次表现不好就重写整套计划；不要为了让图表好看而填充缺失数据；不要把来源人物姓名写成用户必须遵循的权威命令。

## 交付方式

用户只想要答案时，直接对话；用户要求“建立系统”“保存档案”或“输出完整资料”时，在`fitness-reports/`创建一组不覆盖已有文件的Markdown/CSV资产，并在主报告中列出文件清单。每份资产都标注生成日期、数据范围、未知项和下一次更新条件。
