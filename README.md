# Healthy Fitness Coach Skill

> 面向18～55岁普通人群的健康健身教练Skill：把训练计划、动作执行、饮食恢复和数据复盘串成一个可持续的闭环。

Healthy Fitness Coach适用于健身新手与普通进阶者，支持每周训练规划、今日训练辅助、训练日志分析、趋势面板和渐进式调整。它强调长期健康、可解释的建议与真实数据，不鼓励药物增强、极端减脂或以伤病为代价的训练。

## 它能解决什么问题？

很多健身建议只回答“今天练什么”，却没有回答：是否适合你、如何记录、怎样判断有效、什么时候该调整。这个Skill以**ABCDE闭环**组织建议：

- **A—Assessment｜评估**：了解目标、训练基础、时间安排、睡眠、营养与安全风险。
- **B—Building plan｜建立计划**：生成符合频率、器械、时间和恢复能力的训练与饮食策略。
- **C—Coaching｜执行辅导**：在训练当天给出热身、动作要点、组次、强度、休息与替代动作。
- **D—Data review｜数据复盘**：从训练日志识别训练量、频率、强度、动作覆盖和恢复趋势。
- **E—Evolution｜持续调整**：依据表现、主观用力程度、体重和反馈，逐步调整计划，而不是频繁推翻重来。

## 核心能力

### 🧭个体化训练规划

根据目标（增肌、减脂、体态改善或综合健康）、每周可用时间、训练场地和经验，设计可执行的训练安排，并提供动作替代、进阶与降阶方案。

### 🏋️今日训练助手

从热身开始，按训练顺序给出动作、组次、重复次数、强度区间、休息时间和技术提示；训练中可根据疲劳、器械占用和动作反馈即时调整。

### 📊训练数据分析

支持手工日志、导出文本和训记数据。可以分析训练频率、部位分布、有效组、重量与重复次数变化、训练间隔、连续性及潜在过度训练信号。

### 📈趋势面板

将结构化训练数据生成本地自包含HTML面板，直观看到训练次数、训练量、动作表现和周期趋势，便于复盘与长期追踪。

### 🥗饮食与恢复建议

围绕蛋白质、总能量、体重变化、睡眠、压力和日常活动给出可执行建议；优先采用可持续的小步调整，不追求极端热量缺口。

### 🛡️安全边界

在建议训练前进行基础安全筛查。出现胸痛、晕厥、异常心悸、轻微活动即明显气短或进行性麻木无力等情况时，停止生成训练处方并建议寻求专业评估。

## 使用方式

### 方式一：独立Skill

适合不需要连接健身App的场景。安装[`healthy-fitness-coach/SKILL.md`](healthy-fitness-coach/SKILL.md)对应的Skill，直接通过对话提供个人情况、训练目标或日志即可使用。

可安装的打包文件：[`dist/healthy-fitness-coach.skill`](dist/healthy-fitness-coach.skill)

独立模式支持两种输出：

- **持续对话**：边训练边询问，实时调整当天安排。
- **Markdown交付**：一次性生成训练计划、周期复盘或可保存的分析报告。

### 方式二：连接训记（推荐的普通用户路径）

不需要安装Node、不需要运行命令，也不需要添加Plugin。安装Skill后，直接对我说：

```text
我想连接训记。
```

我会先询问你是否确认连接。确认后，你可以任选一种方式提供训记官方说明：

- 直接复制训记的导入/导出调用说明；
- 发送官方说明截图；
- 同时提供训记Open API Key。

我会从说明或截图中识别Base URL、接口路径、鉴权方式、请求参数和返回格式，然后按官方规则读取训记数据。Key只用于本次连接，不会在回复中展示，不会写入GitHub、Markdown、报告或项目文件。

连接成功后，你只需要继续说：

```text
分析我最近4周的训记数据，生成趋势面板。
```

读取会优先使用本地缓存，避免同一天重复请求；如果要修改训练记录，我会先展示预览，得到你的明确确认后再按训练ID写回。

### 高级方式：CodexPlugin自动同步

如果你希望长期在本机自动读取训记，可选安装[`healthy-fitness-coach-plugin/`](healthy-fitness-coach-plugin/)。这条路径适合熟悉Node和CodexPlugin的用户，普通用户不需要使用。

## 训记数据闭环

训记接入分为四步，数据始终以用户确认和服务端返回结果为准：

1. **读取**：调用训记导出接口，按日期或日期范围获取训练记录，并缓存到本地，避免重复请求。
2. **分析**：解析训练ID、训练时间、动作、组次、重量、次数和有氧指标，形成训练趋势与问题清单。
3. **预览**：整理训练记录后先生成写回预览，检查日期一致性、记录数量、字符长度和ID是否保留。
4. **写回**：用户明确确认后，调用训记upsert接口按训练ID更新或新建；这不是整天覆盖删除，且以服务端返回的`res`作为最终缓存结果。

典型请求示例：

```text
分析我最近4周的训记数据，告诉我训练频率、各部位训练量和主要趋势。
生成最近30天的训练趋势面板，并给出下个周期的3条调整建议。
把今天的训练记录整理成适合写回训记的格式，先给我预览，不要直接写入。
```

## 输出原则

- 建议会说明依据、假设和不确定性，区分数据事实与推断。
- 同时考虑训练刺激、恢复、营养、体重、动作质量、时间成本和依从性。
- 以渐进超负荷、足够恢复和稳定执行为主，不鼓励追求疼痛、力竭或夸张外观。
- 不替代医生、康复师或营养师的诊断与治疗；有疾病、用药、孕期或近期手术/急性外伤时，应先获得专业意见。
